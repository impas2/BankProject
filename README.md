# BankProject

Учебная модель банковского счёта на Python 3.9+.

## Стиль кода

Оформление проверяет Ruff; настройки находятся в `pyproject.toml`.
Для редактора добавлен `.editorconfig`.

- Классы и исключения — `PascalCase`: `BankAccount`, `InvestmentAccount`,
  `AccountFrozenError`.
- Модули, функции, параметры и переменные — `snake_case`: `bank_account.py`,
  `validate_amount`, `active_account`.
- Элементы перечислений — `UPPER_SNAKE_CASE`: `AccountStatus.ACTIVE`.
- Внутренние атрибуты начинаются с одного подчёркивания: `_balance`.
- Отступ — четыре пробела, строки оформляются двойными кавычками,
  длина строки для форматтера — 88 символов.
- Импорты разделены на стандартную библиотеку, сторонние зависимости
  и модули проекта; внутри групп порядок проверяет Ruff.
- Сигнатуры методов и фикстур снабжены аннотациями типов.
  Аннотации сами по себе не проверяют входные данные во время выполнения.

Настройки основаны на [документации Ruff](https://docs.astral.sh/ruff/configuration/)
и [Ruff Formatter](https://docs.astral.sh/ruff/formatter/).

## Команды

Выполняйте команды из корня BankProject. Установить зависимости
из зафиксированного набора версий:

```bash
uv sync --locked
```

Проверить оформление и запустить существующие тесты:

```bash
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked python -m pytest -q
```

Применить автоматические исправления и форматирование после новых изменений:

```bash
uv run --locked ruff check --fix .
uv run --locked ruff format .
```

Ruff проверяет импорты, названия, неиспользуемые и неопределённые имена,
а форматтер — пробелы, отступы, кавычки и переносы строк.

## Изменения при применении стиля

Исходники и тесты приведены к единому оформлению. Удалён неиспользуемый
импорт `NaN`; класс `investment_account` переименован в `InvestmentAccount`.
Его базовый класс теперь импортируется как `BankAccount`, а не как модуль;
добавлен недостающий импорт `AccountStatus`.

В тестах используются понятные имена фикстур `active_account` и
`frozen_account`, без промежуточных переменных `account1` и `account2`.
Существующие свойства `get_balance` и `get_account_type` сохранены.

Пустой `src/models.py`, перекрывавший каталог с моделями, заменён на
`src/models/__init__.py`. Настройки pytest добавляют `src` в путь импорта.
Поэтому тесты запускаются из корня проекта без ручного задания `PYTHONPATH`.

## Валидация при создании счёта

Конструктор `BankAccount` проверяет валюту, а `AbstractAccount` — общие
поля счёта. Все проверки выполняются до сохранения атрибутов объекта.

- `balance` — конечный неотрицательный `Decimal`; `NaN`, бесконечность,
  числа других типов и строки отклоняются. По умолчанию баланс равен нулю.
- `currency` — элемент `Currency`: RUB, USD, EUR, KZT или CNY.
  Строки, включая `"USD"` и `"BTC"`, не принимаются.
- `account_id` — объект `UUID`; при явно переданном `None` создаётся новый
  идентификатор через `uuid.uuid4()`.
- `account_number` — непустая строка, содержащая хотя бы один непробельный
  символ. При явно переданном `None` генерируется строка UUID.
  Переданный номер сохраняется без изменений, включая начальные нули.
- `person` — объект `Person`, `account_type` — элемент `AccountType`.

При неверных данных выбрасывается `InvalidOperationError`.
Сценарии создания счёта проверяются в `tests/test_account_creation.py`.

После добавления валидации проходят все 50 тестов и проверка форматирования.
Проверка Ruff изменённых модулей и новых тестов также проходит.
Общая проверка Ruff пока сообщает о четырёх прежних ошибках `F821`:
в `premium_account.py` и `savings_account.py` не импортированы
`BankAccount` и `AccountStatus`.

## Оставшиеся задачи по логике

- Генерируемый номер счёта пока представляет собой полный UUID,
  а не короткий номер из задания.
- Содержимое полей `Person` отдельно не валидируется;
  некорректный тип статуса в сеттере счёта молча игнорируется.
- `InvestmentAccount`, `PremiumAccount` и `SavingsAccount` остаются
  заготовками: их конструкторы задают только статус и не вызывают
  конструктор `BankAccount`, поэтому остальные поля не инициализируются
  и общая валидация не выполняется.
